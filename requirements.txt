# ============================================================
# MARKETPULSE - PYTHON PROJECT DEPENDENCIES
# ============================================================
#
# 1. WHAT THIS FILE IS FOR
# ------------------------------------------------------------
# This file records the Python packages that pip should install
# for my project's environment.
#
# Installation command:
# python -m pip install -r requirements.txt
#
# This file supports local setup and deployment. It does not
# contain my Django views, database models, or trading logic.
#
# Lines starting with # are explanatory comments.
# pip ignores these comments when installing the packages.
#
#
# 2. HOW TO READ EACH REQUIREMENT
# ------------------------------------------------------------
# Example: Django==5.2.17
#
# Django   : the package name.
# ==       : requires the exact version written after it.
# 5.2.17   : the package version.
#
# Here, == is dependency-version syntax. It is not a Python
# comparison between variables.
#
# Example: django-anymail[brevo]==15.2
#
# [brevo] requests the package's optional Brevo dependencies.
# It is package-installation syntax, not a Python list.
#
# Exact versions help recreate the environment, but successful
# installation still depends on Python/platform compatibility
# and the packages being available from the package index.
#
#
# 3. HOW THIS FILE CONNECTS TO MY PROJECT
# ------------------------------------------------------------
# requirements.txt
#   -> pip installs packages in the Python environment.
#   -> My Python modules can import those installed packages.
#   -> Django settings configure the integrations I want to use.
#   -> Views, models, services, and tasks use those integrations.
#
# Installing a package does not automatically enable its feature.
# For example:
# - Celery needs task and worker configuration.
# - Email delivery needs provider settings and credentials.
# - Database access needs Django DATABASES configuration.
# - JWT authentication needs explicit authentication setup.
#
#
# 4. MY DJANGO FRAMEWORK CONNECTIONS
# ------------------------------------------------------------
# Django uses a Model-Template-View architecture:
#
# URL configuration:
# Matches a requested address to a view.
#
# View:
# Handles the request and coordinates application logic.
#
# Model and ORM:
# Represent stored data and query the configured database.
#
# Template:
# Produces HTML using the context supplied by a view.
#
# Typical interaction:
# Browser request -> URL -> View -> Model/Service
#                            -> Template -> HTML response
#
# API interaction:
# Frontend request -> API URL -> DRF View -> Model/Service
#                                        -> JSON response
#
# These interactions are implemented in other project files.
# requirements.txt supplies the packages that support them.
#
#
# 5. LEARNING CONCEPTS RELEVANT TO THIS FILE
# ------------------------------------------------------------
# Modules and packages:
# pip installs third-party packages that Python can import.
# Installation names can differ from Python import names.
#
# Networking:
# HTTP clients and API libraries support external data access.
#
# Databases:
# Database drivers allow Django to communicate with PostgreSQL.
#
# Deployment:
# Server and static-file packages support hosting the application.
#
# Python features such as variables, loops, classes, functions,
# and exception handling belong in my .py files. They are not
# implemented by the dependency lines in this file.
#
# Some packages are direct dependencies used by project code.
# Others are supporting dependencies used by those packages.
# I would check imports and settings to confirm actual usage.
#
#
# ============================================================
# 6. PACKAGE NOTES - ORIGINAL ORDER PRESERVED
# ============================================================
